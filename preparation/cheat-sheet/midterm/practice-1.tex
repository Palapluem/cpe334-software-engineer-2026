\topic{4) Upload attack: ข้าม trust boundary}
\b{Browser check ถูกข้าม → script ปลอม PDF → server เก็บแบบรันได้ → เปิด URL → script อ่านรายงานคนอื่น}
\k{Actor}: นักศึกษาข้ามการตรวจใน browser; \k{Assets}: รายงานผู้อื่น/ระบบ; \k{Surface}: upload API/file URL; \k{Boundary}: client → server และไฟล์ข้อมูล → โค้ดที่รัน
\k{CIA}: อ่านรายงานคนอื่นละเมิด C; code execution เสี่ยง I/A ด้วย \r{แยกเหตุที่เกิดแล้วจากผลที่อาจเกิด}
\k{Control/test 1}: server ตรวจ PDF type/content/size; ส่ง script, MIME ปลอมหรือไฟล์ใหญ่ → 4xx ไม่เก็บเป็นรายงาน
\k{Control/test 2}: เก็บนอก webroot/รันไม่ได้; download handler ตรวจ owner; เปิด script → ไม่รัน; ขอรายงานคนอื่น → ปฏิเสธ
\extra สุ่มชื่อไฟล์ ตรวจ path จำกัดสิทธิ์ สแกนมัลแวร์ตามความเสี่ยงและ log อย่างปลอดภัย; ตรวจใน browser ช่วย UX ไม่ได้แทน server
\topic{ตอบ security พร้อมเหตุผล}
\b{ช่องโหว่ → จุดเข้า/asset → boundary → CIA → defense → negative check + expected}; ไม่ใช่แค่รายชื่อ attack
\k{อย่าสับสน}: XSS รันใน browser; CSRF ใช้ browser/cookie ส่งคำสั่ง; SSRF ให้ server ดึง URL; SQLi เปลี่ยนความหมาย query; defenses/tests ดูหน้า 1
\k{Boundary}: จำกัด 3 → ทดสอบ 2/3/4, ข้ามภาค, ยกเลิกแล้วนับไหม? เงื่อนไขที่โจทย์ไม่บอกต้องถาม ไม่เพิ่มกฎเอง
\k{แยกศัพท์}: threat = เหตุร้ายที่อาจเกิด; vulnerability = จุดอ่อน; attack = การใช้จุดอ่อน; risk ประเมินโอกาส/ผลกระทบ; control = มาตรการลดความเสี่ยง
