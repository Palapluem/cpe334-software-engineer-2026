\topic{Git: graph = ancestry + pointers}
\k{HEAD → branch → commit}: เมื่อ clean ไฟล์ตรง HEAD; \k{origin/*} = remote ล่าสุดที่ local ทราบ \r{ไม่ใช่ GitHub สด}; tag ชี้ commit คงที่
\k{switch}: เปลี่ยน HEAD/working tree ไม่เลื่อน branches; \k{commit}: สร้างลูก HEAD แล้วเลื่อน current; \k{merge}: รวมเข้า current ไม่เลื่อน source
\k{FF}: current เป็น ancestor ของ target → เลื่อน current ไม่สร้าง commit; \k{3-way}: แยกสาย → commit ใหม่ 2 parents; \r{graph ไม่บอกว่าจะมี file conflict}
\topic{คำอธิบายเสริม A: FF → commit → switch}
เริ่ม A → B → C → D → E; main=B, staging=C, feature=E (HEAD); origin/main=B, origin/staging=C; ภาพย่อชื่อ branch จากคำสั่ง
\cl{git switch sprint\_1\_staging}
\cl{git merge feature/load\_scores}
แก้ \code{score\_data.py}/\code{scores.csv}; เพิ่ม \code{validation\_notes.txt}
\cl{git status; git diff -- score\_data.py scores.csv}
\cl{git add score\_data.py scores.csv validation\_notes.txt}
\cl{git diff --cached}
\cl{git commit -m "Document score validation cases"}
\cl{git switch main}

\topic{Sample 2.8: สร้าง feature จากฐานหลัง FF}

\topic{Sample 2.9: อัปเดต staging ก่อนรวม feature}
เริ่ม staging=D, origin/staging=G; D → E → F อยู่บน feature และ D → G แยกอีกสาย
\cl{git switch sprint\_2\_staging}
\cl{git merge --ff-only origin/sprint\_2\_staging}
\cl{git merge feature/export\_results}
\cl{git push origin sprint\_2\_staging}
