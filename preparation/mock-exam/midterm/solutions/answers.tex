\qtitle{1}{วิเคราะห์ความต้องการ}{8}
\textbf{คำย่อ:} FR = Functional Requirement; NFR = Non-functional Requirement\par
\anshead{1.1 ดู workshop ที่เปิดลงทะเบียน}{2}
เป็น FR เพราะให้ Student ที่เข้าสู่ระบบดู workshop เพื่อเลือกลงทะเบียน; “เปิดลงทะเบียน” ต้องนิยามให้ชัด จึงปรับให้แสดงเฉพาะรายการเปิดตามเกณฑ์ที่ยืนยัน; ทดสอบเปิด/ปิด ต้องแสดงรายการเปิดครบและไม่แสดงรายการปิด

\anshead{1.2 ลงทะเบียนรวดเร็ว}{2}
เป็น NFR ด้าน performance เพราะมุ่งความเร็ว แต่ “รวดเร็ว” ไม่มีเกณฑ์วัด; เสนอให้ 95\% ของคำขอตอบใน 2 วินาทีที่ 100 ผู้ใช้พร้อมกัน (รอยืนยัน) โดย load test วัดตั้งแต่ submit ถึงผลตอบกลับและตรวจว่าผ่านเกณฑ์

\anshead{1.3 ไม่เกิน 3 workshop ต่อภาค}{2}
เป็น business/domain rule เพราะจำกัดจำนวนตามนโยบาย; “ไม่เกิน 3 ต่อภาค” วัดได้ จึงคงไว้แต่ยืนยันสถานะที่นับ; ทดสอบมี 2 เพิ่มเป็น 3 ต้องผ่าน และมี 3 ขอเพิ่มเป็น 4 ต้องถูกปฏิเสธโดยยอดยังเป็น 3

\anshead{1.4 ยกเลิกและดูรายชื่อ}{2}
เป็น FR แต่ไม่ atomic เพราะรวมสองความสามารถ; แยกเป็น Student ยกเลิกการลงทะเบียน และ Coordinator ดูรายชื่อผู้เข้าร่วม; ยืนยันเงื่อนไข/สิทธิ์แล้วทดสอบตามบทบาท ต้องยกเลิกได้เฉพาะที่อนุญาตและรายชื่อตรงข้อมูล\par\smallskip
\textbf{เกณฑ์ตรวจต่อข้อย่อย 2 คะแนน:} ประเภทพร้อมเหตุผล 0.25; จุดประสงค์ 0.25; คุณภาพ 0.50; วิธีตรวจและผลคาดหวัง 0.50; ปรับหรือคงข้อความพร้อมเหตุผล 0.50 ข้อ 1.2 รับ NFR ด้าน usability หากนิยามและวิธีวัดสอดคล้องกัน

\anshead{12.3 Inspect, stage และ commit}{5}
\begin{verbatim}
git status
git diff -- score_data.py scores.csv
git add -- score_data.py scores.csv validation_notes.txt
git diff --cached -- score_data.py scores.csv validation_notes.txt
git commit -m "Document score validation cases"
\end{verbatim}
\textbf{เหตุผลสั้น:} \code{status} ดูสถานะ; \code{diff} ดู tracked changes; \code{diff --cached} ตรวจเนื้อหาทั้งสามไฟล์รวมไฟล์ใหม่หลัง stage และก่อน commit รับคำสั่งอื่นที่ตรวจครบและ stage เฉพาะสามไฟล์

F มี parent E เพียงตัวเดียวและรวมการแก้สามไฟล์; sprint\_1\_staging = F (HEAD ชี้ branch นี้), feature/load\_scores = E, main และ origin/main = B, origin/sprint\_1\_staging = C เพราะไม่มี push จึงคง remote-tracking refs เดิม

\textbf{เกณฑ์ตรวจ 5 คะแนน:}
\begin{itemize}
\item Inspect เห็นสถานะและเนื้อหาการเปลี่ยนแปลงที่จะ commit รวมไฟล์ใหม่ 1
\item Stage ชื่อไฟล์สามรายการชัดเจน ไม่ใช้ \code{git add .} 1
\item Commit ด้วยข้อความที่กำหนด 1
\item F ต่อจาก E และ local sprint/HEAD ไป F 1
\item pointers อื่นคงครบและไม่สร้าง merge commit แทรก 1
\end{itemize}
